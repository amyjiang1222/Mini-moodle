# Mini Moodle 需求基線（本地草稿）

## 目標與角色

以簡化的教學平台展示 Agile + AI 流程。角色為教師與學生；只實作 Jira MM-1、MM-2、MM-9、MM-3、MM-4 對應的最小流程。這份文件由 AI 整理，等待團隊人工確認。

## 功能需求

| ID | 需求 | 來源 |
| --- | --- | --- |
| R1 | 有效帳密登入；錯誤帳密顯示提示；依教師或學生角色限制功能 | MM-1 |
| R2 | 教師建立課程，輸入非空名稱及描述；建立後顯示於清單並取得 2 大寫字母 + 7 數字課碼 | MM-2 |
| R3 | 學生以課碼加入課程，加入後可查看課程內容 | MM-9 |
| R4 | 課程教師發布及修改標題與內容非空的公告，課程學生可查看但不可修改 | MM-3 |
| R5 | 課程成員發布及查看留言；留言顯示發言者與內容；空白留言遭拒絕 | MM-4 |

## 界線與待決事項

- 帳號由本機管理指令建立；沒有公開註冊、忘記密碼、檔案繳交或評分功能。
- 未加入課程的學生及非授課教師不能查看該課；MM-9 已補上學生非成員的限制，非授課教師仍採相同的保守存取規則。
- 課程「管理」目前只包含建立與查看，不包含更名、刪除或轉交。
- 公告修改範圍是原課程教師可改標題與內容；不提供版本歷史或刪除。這項實作選擇由使用者於 2026-10-26 授權 AI 判斷，已同步至 Jira MM-3。
- 不在本地原型建立真實使用者個資。展示帳號應使用虛構資料。

## 品質與驗證

- 密碼以 Werkzeug 雜湊儲存，資料庫查詢使用參數，POST 表單檢查 CSRF token。
- 教師、學生與非成員的權限以整合測試驗證。
- 使用 SQLite，資料留在本機 `instance/`；不把資料庫或密碼放入 Git。
- HTML 模板自動跳脫使用者文字；本服務目前只供課堂本機展示。

## 人工接受關卡

AI 可提案故事、驗收條件與程式碼；Product Owner 接受故事與範圍，團隊決定估點和 Sprint，組員審核程式碼後再提交到共用版本庫。此處的測試通過僅表示本地實作符合目前列出的檢查。
